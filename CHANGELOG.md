## 0.1.5 (unreleased)
- Add `DurableServer.Backends.LTXStore`, an optional backend wrapper that persists each key as a log of LTX segments (the Litestream model) instead of one full-state object, so a sync ships only the pages of the encoded state that changed — ~3% of full-state bytes for a point mutation of a 1 MiB state, under 1% for appends. The head object at the key keeps the etag CAS, `try_claim`, conditional-delete, and ambiguous-conflict-recovery semantics of the wrapped backend, so ownership and fencing behavior are unchanged; segments are immutable, nonce-named objects under the reserved `__ltx/` namespace. States encoding to at most `:inline_threshold_pages` pages (default 4) are embedded in the head at exactly the plain backend's one-PUT cost; manifests reaching `:max_segments` (default 16) reset the log with one snapshot segment and eagerly delete superseded segments. Restores verify every file checksum, the TXID chain, the checksum chain, and the final rolling checksum, failing closed — never `:not_found` — on any inconsistency; pre-existing plain objects read through unchanged and convert on their next write. `LTXStore.sweep_orphans/2` collects segments abandoned by lost head-CAS races and is safe to run anywhere, anytime. Compose with `DurableServer.Backends.EncryptedStore` as the *wrapped* backend to seal heads and segments per object with storage-key binding (sealing above the segment layer would defeat deltas entirely). Storage subscriptions are not supported by this backend; heartbeat tracking falls back to `:poll`.
- Add `DurableServer.LTX`, a pure-Elixir reader/writer for LTX v3 (header/page-frame/trailer marshaling, CRC-64/GO-ISO, LZ4 block codec, varint page index, rolling database checksums) verified bidirectionally against the Go reference implementation (`superfly/ltx` v0.5.2) — fixtures it encodes verify here and files encoded here verify under the Go decoder — plus `DurableServer.LTX.Compactor`, which merges TXID-contiguous segment files with two checks stricter than the reference: exactly-adjacent inputs must agree across the checksum chain, and a compacted snapshot must reproduce the rolling checksum it claims. `DurableServer.LTX.PagedTerm` maps arbitrary terms onto page images with deterministic encoding and incremental (byte-compare) checksumming.
- Add optional backend-independent envelope encryption through `DurableServer.Backends.EncryptedStore`, with per-object content keys, X25519 HPKE key wrapping for up to 32 recipients, ChaCha20-Poly1305 authentication, and storage-key binding. The encrypted payload is a canonical, backend-agnostic encoding of the caller's exact term (atom keys, pids, and references all survive unchanged) rather than a round trip through the wrapped backend's own codec; this superseded an earlier internal shape, so an object sealed by a pre-release build of this branch now fails closed instead of silently returning a stale encoding — with `{:error, :compressed_payload_rejected}` for a payload the earlier build compressed, or `{:error, :unrecognized_payload_format}` for one it did not. The write and read paths enforce the same 16 MiB bound on the encoded payload from one shared constant: an oversized write now fails immediately with `{:error, {:payload_too_large, size}}` instead of succeeding and leaving behind an object nothing can read back. Existing plaintext objects remain readable by default (`plaintext_compat: :permissive`) and are logged, not emitted as telemetry, on every fallback read; pass `plaintext_compat: :strict` to reject unmarked objects instead.
- Support wrapping a managed EKV backend (`data_dir`/`cluster_size`/`node_id`) with `DurableServer.Backends.EncryptedStore`, deriving a matching encrypted, split heartbeat store — carrying forward the same recipient keys, decryption key, and `plaintext_compat` — when none is given explicitly. Previously this configuration crashed at `start_link`.
- Return the real underlying error from `start_child/3` (`existing: true`) and `ensure_started_child/3` when a persisted object exists but fails to read or decode, instead of collapsing it to `{:error, :not_found}`; `ensure_started_child/3` no longer treats that failure as "never existed" and starts a fresh child over the intact persisted state. Callers must no longer treat any `{:error, _}` from these calls as safe to retry as a fresh start.
- Exclude the raw decryption key from `DurableServer.Backends.EncryptedStore`'s inspected state so it can no longer appear in OTP's default crash logs.
- Add `:heartbeat_future_skew_tolerance_ms` supervisor option (default: `5_000`). Node heartbeats stamped further than this into the future are ignored for liveness decisions instead of being treated as always-fresh, and local heartbeat/watchdog deadlines now use monotonic time so wall-clock (NTP) adjustments no longer stretch or shrink safety windows.
- Reject child keys in the reserved internal `__nodes/` namespace: `start_child/3`, `ensure_started_child/3`, and `rehome_child/3` now raise `ArgumentError` for keys that would collide with node heartbeat storage.
- Enforce `max_children` limits atomically with local capacity reservations so concurrent starts can no longer exceed total or per-module limits. Integer `max_children` is enforced through the same path and returns `{:error, {:capacity_limit, :max_children_total}}` instead of leaking DynamicSupervisor's raw `{:error, :max_children}`; integer values must now be positive (`0` or negative raises `ArgumentError`).
- Terminate servers using `auto_sync: true` when a storage CAS conflict shows the object was replaced by another owner, matching explicit and periodic sync behavior. Previously the stale process logged the conflict and kept serving requests.
- Accept documented callback returns that previously crashed the process: integer timeout actions (e.g. `{:reply, reply, state, 5_000}`) and `{:stop, {:shutdown, :normal}, ...}` stops, which persist `:stopped_graceful` while preserving the exit reason.
- Return `{:error, reason}` from `terminate_and_delete_child/2,3` when the storage delete fails instead of `:ok`, and only delete storage after an owned `:deleting` tombstone is CAS-written so a stale process cannot delete an object claimed by a newer owner.
- Fence crash-time metadata writes to the dying owner so a stale crashing process cannot overwrite a newer owner's status or crash history.
- Release the storage prefix claim when a supervisor stops or fails to start. Supervisors can now be restarted with the same `:prefix` in the same VM; previously the claim leaked until VM restart.
- Bound graceful shutdown with a new `graceful_shutdown_total_timeout_ms` deadline (default: `55_000`) shared by discovery shutdown and all children, while preserving `graceful_shutdown_timeout_ms` as each child's persistence window, and warn when children fail final persistence during shutdown.
- Cap remote placement ERPC calls and remote child timeouts by the caller's remaining deadline instead of issuing fresh fixed per-node timeouts after the budget expired.
- Enable Req's transient retries for heartbeat writes within the heartbeat deadline instead of crashing the supervisor tree on the first retryable HTTP or transport error.
- Recover from discovery task crashes by logging, clearing discovery state, and rescheduling instead of restarting the whole supervisor tree.
- Make mirror fallback promotion create-only (`try_claim`) so promotion can no longer overwrite an object concurrently created in the preferred backend.
- Retry waiting `ensure_started_child/3` callers immediately when the singleflight leader finishes before the waiter registers instead of sleeping until the full timeout, and never run the guarded operation twice when it raises `ArgumentError`.
- Harden persisted metadata decoding with bounded sizes, `:safe` external-term decoding, and per-field validation. Corrupt or unsafe metadata is rejected with `{:error, %ArgumentError{}}` from storage reads instead of being admitted as partially typed data; legacy binary node references remain accepted.
- Parse IAM XML responses with DTDs disabled and a 1 MiB limit to prevent external-entity and entity-expansion attacks from a malicious endpoint.
- Redact secrets from logging: IAM CreateAccessKey bodies (which contain `SecretAccessKey`) are no longer logged, supervisor startup logs omit backend state and `init_info`, and backend errors no longer echo raw options.
- Update Mint to 1.9.3 for the HTTP/1 chunk-size parser security fix (CVE-2026-59249).
